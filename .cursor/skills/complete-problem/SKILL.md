# 問題完了

現在の問題を完了扱いにし、進捗表を更新したうえで **次の問題のスケルトンファイル** を用意する。

## 前提

- 進捗の正本はリポジトリ直下の `problems.md`
- 解答ファイルはリポジトリ直下の `*.go`（`package main`）
- ファイル名は LeetCode スラッグのスネークケース（例: `group-anagrams` → `group_anagrams.go`）
  - 既存の例外（`neet_code_1.go` など）はそのまま残し、**新規はスラッグ準拠**

## ワークフロー

```
1. 完了対象の特定 → 2. problems.md 更新 → 3. 次問の特定 → 4. 次問 .go 作成 → 5. 結果報告
```

### Step 1: 完了対象の特定

ユーザー指定がなければ次で推定する:

1. 会話・最近編集した解答 `.go`
2. `problems.md` で `解答` 列にそのファイルがあり `[ ]` の行
3. それでも不明なら、完了した問題名または番号を1問だけ確認する

完了条件の確認（足りなければ確認してから進む）:

- 解答 `.go` が存在する
- 問題に対する解法関数が入っている（空スケルトンだけなら完了にしない）

### Step 2: `problems.md` を更新

完了行を次の形にする:

| 列 | 更新内容 |
|----|----------|
| 状態 | `[ ]` → `[x]` |
| 解答 | `—` → `[filename.go](./filename.go)` |
| メモ | ユーザーが書いた／依頼したメモがあれば追記。なければ触らない |

例（Group Anagrams 完了時）:

```markdown
| 4 | [x] | [Group Anagrams](https://leetcode.com/problems/group-anagrams/) | Medium | [group_anagrams.go](./group_anagrams.go) | |
```

同じ問題を二重完了にしない。すでに `[x]` なら状態は変えず、解答リンクだけ欠けていれば補う。

### Step 3: 次の問題を特定

`problems.md` を上から見て、**最初の `[ ]` 行**を次問とする（カテゴリをまたいでもよい）。

- 全問 `[x]` なら次ファイルは作らず、その旨だけ報告する
- ユーザーが「次は #N」と指定していればそれを優先する

### Step 4: 次問の `.go` を作成

パス: `./{leetcode_slug_with_underscores}.go`

すでに同名ファイルがある場合:

- 中身がスケルトン／未完成なら上書きしない（既存を使う旨を報告）
- 完成解があるなら `problems.md` の次問選定を見直し、ユーザーに確認

#### ファイルひな形

既存の `contains_duplicate.go` / `group_anagrams.go` に合わせる。**解法・擬似コード・ヒントは書かない**（解くのはユーザー）。

```go
package main

// {日本語の問題文（1〜3文）}
// Input: {代表例の入力}
// Output: {代表例の出力}
// https://leetcode.com/problems/{slug}/

func {関数名}({引数}) {戻り値} {
}
```

| 項目 | ルール |
|------|--------|
| 問題文 | 日本語。LeetCode の要旨を短く。制約の丸写しは不要 |
| Input / Output | 公式の代表例を1組 |
| URL | `problems.md` のリンク（必要なら `/description/` 付きでも可） |
| 関数シグネチャ | 言語は Go。一般的な LeetCode シグネチャ。本体は空 |
| 考え方コメント | **入れない**（完了済みファイルへの追記はユーザー判断） |

問題文やシグネチャが不確かなときは、URL とタイトルから妥当なものを置き、不確かな点を報告末尾に1行で書く。

### Step 5: 結果報告

短く報告する:

1. 完了にした問題（番号・タイトル・解答ファイル）
2. 作成した次問ファイル（番号・タイトル・パス）
3. 次に解く内容の一文（問題文の要約）

## やらないこと

- 次問の解法・答え・詳細ヒントをファイルや返答に書かない
- `problems.md` 以外の進捗ファイルを勝手に増やさない（ユーザー指定時のみ）
- 完了問題の解答コードをリファクタしない（依頼時のみ）
- git commit しない（依頼時のみ）

## トリガー例

- 「Group Anagrams 完了した」
- 「この問題終わった。次を用意して」
- 「complete-problem」
